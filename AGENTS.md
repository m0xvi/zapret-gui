# AGENTS.md — инструкция для ИИ-агента, продолжающего работу над Zapret GUI

> Быстрый старт. Полный контекст, карта кода, факты о движке и список открытых вопросов —
> в **[docs/HANDOFF.md](docs/HANDOFF.md)**. Прочитайте оба файла до первого коммита.

---

## 1. Что это за проект

**Zapret GUI** — Windows-приложение (**C# .NET 8 + WPF**, MVVM) — графическая надстройка над
популярной сборкой [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube)
(обход DPI для YouTube/Discord, утилита `winws.exe` из zapret от bol-van).

Ключевые принципы, которые нельзя нарушать:

1. **Приложение не содержит и не перепаковывает бинарники zapret.** Движок (`bin/winws.exe`,
   `WinDivert64.sys`, списки, `.bat` стратегий) скачивается с официального репозитория
   Flowseal по кнопке на странице «Обновления».
2. **Стратегии не хардкодятся.** GUI парсит те же `general*.bat`, что и оригинальная сборка
   (см. `Core/StrategyParser.cs`). Любая новая стратегия в релизах Flowseal должна появляться
   в интерфейсе автоматически, без изменений кода — это главное архитектурное решение.
3. **Обновление движка никогда не затирает пользовательские данные** (`*-user.txt`, режимы
   `ipset` и игрового фильтра, `ACTIVE_*.bin`, `.backup`-списки). См. `EngineService.CopyEngine`.

## 2. Язык и стиль

- **Весь UI-текст, комментарии в коде, README, описания коммитов — на русском.** Аудитория
  проекта — русскоязычные пользователи Windows.
- `ImplicitUsings` **выключены намеренно** (`UseWPF` + `UseWindowsForms` дают конфликты имён
  `MessageBox`/`Application`/`Timer`). Пишите явные `using` в каждом файле.
- Nullable включён: новые свойства/методы — с корректными `?`.
- MVVM: бизнес-логика только в `Core/` и `ViewModels/`, в code-behind страниц — лишь
  подключение DataContext, подписки на события, работа с визуальным деревом.
- Кисти в XAML — только через `{DynamicResource XxxBrush}`, иначе переключение темы сломается.
- Ключи ресурсов и `{Binding}` **не проверяются компилятором** — после правок XAML обязательно
  прогоните `python3 tools/check_bindings.py` (см. §4).

### Информационная архитектура (этапы 1–8, `v1.17.25` … `v1.24.0`)

- Структура зафиксирована в [`docs/IA_REDESIGN.md`](docs/IA_REDESIGN.md) и полностью внедрена:
  **пять разделов** — Главная · Обход · Проверки · Автоматизация · Настройки, плюс **«Помощь»**
  в подвале меню и **поиск `Ctrl+K`**. Ограничения: до подраздела не больше двух кликов, функции
  не дублируются между разделами, техническое скрыто по умолчанию.
- Переименования касаются **только подписей**: ключи `Navigate` и `_pages` (`monitoring`, `dpi`,
  `deep-check`, `results`, `logs`, `strategies`, `user-lists`, `profiles`, `updates`, `about`)
  сохранены для трея, шапки и старых ссылок. Формат `AppSettings` не переименовывается — только
  добавляются новые ключи, иначе ломаются профили и бэкапы пользователей.
- Любой новый элемент интерфейса обязан иметь пользовательское имя и попадать в индекс поиска
  с алиасами прежних терминов (см. ниже) — это требование, а не пожелание.

### Режимы «Простой» и «Эксперт» (с v1.22.0)

- По умолчанию — «Простой» (`AppSettings.ExpertModeEnabled = false`); переключатель в шапке, клавиша
  `Ctrl+Shift+E` и карточка «Настройки → Общие → Режим интерфейса». Выбор сохраняется в настройках.
- Экспертные блоки **не переезжают**, а скрываются инлайн: `Visibility="{Binding ExpertMode, Converter=…}"`,
  где `ExpertMode` — зеркало из `MainViewModel` (страницы подписываются на `PropertyChanged`).
- Скрываются технические сущности: матрица 92 тестов, SNI-пул, режимы ipset, аргументы `winws`, интервалы
  и кулдауны, подразделы «Система»/«Глубокая проверка»/«История», отладочный уровень журнала.
- **Опасные операции** (удаление службы, сброс сети, «очистить систему») требуют подтверждения в **обоих**
  режимах — режим не снимает защиту (`docs/IA_REDESIGN.md` §7, правила 2–3).
- Новая функция сначала появляется в «Эксперте» и поднимается в «Простой» только по фидбеку (§7, правило 5).

### Раздел «Помощь» (с v1.23.0)

- Пункт «Помощь» живёт **в подвале меню** (`MainViewModel.NavUtilities`), верхний список — ровно пять
  разделов; в подвал его ставит только UI-коллекция, навигация и подсветка идут через `SelectedUtility`/`IsHelpActive`.
- Правило раздела: **Помощь объясняет, Проверки делают.** В `HelpPage` нет настроек, проверок и состояния —
  только текст, переходы и вызовы уже существующих команд (`ToggleBypassCommand`, `ToggleGameModeCommand`,
  `ExportArchiveCommand`/`ExportReportCommand` и т.д.). Новый сценарий = карточка + существующая команда.
- Кнопки, ведущие в экспертные подразделы («Полный сброс сети» → «Проверки → Система»), скрываются
  в «Простом» режиме — как и сами подразделы (§7).

### Единый стиль карточек и иконки (с `v1.25.0`, семантика — с `v1.26.0`, иконки и доступность — с `v1.27.0`,
зазоры и разгрузка — с `v1.28.0`)

- **Плотность и отступы — только токены** из `Themes/Controls.xaml`: `CardPadding` (18),
  `CardPaddingCompact` (14,12), `CardPaddingList` (8), `InnerCardPadding` (14), `CardGap` (0,14,0,0),
  `BlockGap` (0,12,0,0). Свой `Padding`/литеральный `Margin="0,N,0,0"` у карточки — исключение,
  которое требует комментария в разметке.
- **Кегли — только из шкалы 11 · 13 · 17 · 20 · 25** и только через текстовые стили
  (`DimText` 11 · `BodyText` 13 · `TitleText` 17 · `SubtitleText` 20 · `DisplayText` 25). `FontSize`
  поверх стиля не ставим; иконочные глифы и эмодзи сохраняют собственные размеры.
- **Кисти — только `{DynamicResource XxxBrush}` из `Themes/`**: литеральный `#RRGGBB` в `Views/`
  запрещён (проверяется линтером). Новый ключ добавляется и в `Dark.xaml`, и в `Light.xaml`.
- **Семантика вместо цвета (с `v1.26.0`):** карточка не задаёт `Background`/`BorderBrush`/`BorderThickness`
  вручную — есть `CardAccent` (акцент), `CardWarning`, `CardSuccess`, `CardInfo` (все на базе `Card`).
  Толщина рамки у всех карточек — 1.
- **Регистр текста:** надзаголовок `SectionText` — ЗАГЛАВНЫМИ (`ЧТО ДЕЛАЕТ ПРИЛОЖЕНИЕ`),
  `TitleText` и `SubtitleText` — обычным регистром. Аббревиатуры в скобках тоже заглавные
  (`RTC / WEBRTC / UDP`).
- **Иконки (с `v1.27.0`):** элементы управления и статусы — только MDL2 (`&#xE711;` закрыть, `&#xE721;`
  поиск, `&#xE73E;` галочка, `&#xE945;` молния, `&#xE74D;` удалить) через `FontFamily="{DynamicResource IconFont}"`.
  Эмодзи в `Views/*.xaml` не используются; исключение — подписи разделов и подвкладок в навигации
  (цветовой акцент), они живут в C#.
- **Доступность (с `v1.27.0`):** у иконочной кнопки (в `Content` нет букв) обязателен
  `AutomationProperties.Name`; у `TextBox`/`ComboBox`/`Slider` — тоже (имя = подпись или суть поля,
  не текст-заглушка). `CheckBox` имя получает из `Content` автоматически.
- **Плашки-уведомления (с `v1.27.0`):** фон + рамка одного смысла — только стили
  `NoticeSuccess` / `NoticeWarning` / `NoticeInfo` / `NoticeDanger`; карточки — `Card*`, иконочные
  плитки 32×32 — отдельные Border'ы (линтер их различает по размеру).
- **Зазор между карточками (с `v1.28.0`):** соседние карточки в вертикальном контейнере разделяет
  `CardGap` (или `BlockGap`, если блоки внутри одной карточки); ноль без причины — регрессия, её ловит
  линтер (`зазор < 12 px` — предупреждение). Переключаемые панели в одной ячейке `Grid` и соседи
  по колонкам — не считаются.
- **Размер карточки (с `v1.28.0`):** карточка — один смысловой блок, а не страница: если внутри
  больше двух независимых сюжетов, она делится на 2–3 карточки или `InnerCard`. Практический
  ориентир — 6–9 тыс. знаков разметки на карточку: четыре «монолита» на 7–22 тыс. разгружены
  в `v1.28.0` (`FirstLaunchPage` 22,5 → 6,1 тыс.; `HomePage` 18,1 → 8,6; `UserListsPage` 18,3 → 7,2;
  `StrategiesPage` 7,4 → 6,1). Дальше дробить «Главную» — уже дробление смысла, а не разметки.
- **Кнопки (с `v1.28.0`):** плотность берётся из стиля (`PrimaryButton`, `SecondaryButton`,
  `GhostButton`, а для компактных — `CompactPrimaryButton`, `CompactButton`, `CompactGhostButton`).
  Литеральный `Padding` поверх стиля — исключение для единичной нестандартной плотности 8–11,
  которое нужно оставить осознанно (ряды массовых операций, заголовки карточек, мини-оверлей).
- **Одна настройка — одно место (с `v1.27.0`):** если элемент управления есть в двух разделах,
  остаётся один экземпляр, а на втором месте — ссылка-переход через команду навигации
  (пример: «YouTube (Тяжелый случай)» → `OpenBypassHardSitesCommand`).
- **Перед коммитом:** `python3 tools/check_bindings.py` — ошибки стиля валят проверку
  (литеральный цвет, `Padding` вне токенов, ручные кисти у карточки или плашки, иконочная кнопка
  без подписи), предупреждения (типографика, заголовок карточки, регистр надзаголовка, эмодзи
  в кнопке/заголовке, поле ввода без подписи, слипшиеся карточки без зазора) нужно разбирать,
  а не копить. Линтер не проверяет парность XML — после правок разметки гонять `ET.parse`
  по всем 22 `XAML`.

### Описание инструмента — в подсказке, а не в теле раздела (с `v1.29.2`)

* У каждого блока-инструмента рядом с названием стоит маленький значок **«?»** (`Button Style="{StaticResource HelpHint}"`),
  а пояснительный текст живёт в его `ToolTip` (`AutomationProperties.Name="Подсказка: НАЗВАНИЕ"`).
* Простыня из двух-трёх строк под заголовком карточки — ошибка ревью. Состояние, статус и предупреждения
  остаются видимыми: в подсказку уходит только «что это такое и зачем».
* Селекты — только `Style="{StaticResource AppComboBox}"`. В шаблоне обязателен
  `ContentTemplateSelector="{TemplateBinding ItemTemplateSelector}"`: без него `DisplayMemberPath` не работает и
  в закрытом поле показывается имя класса вместо названия.
* Списки в `AppComboBox` открываются на всю область (`Background="Transparent"` у Grid внутри `Popup`): прозрачная
  «мёртвая зона» между контролом и списком закрывает выпадающий список, как только мышь идёт к пункту.
* Порядок настройки для человека зафиксирован в `docs/SETUP_ORDER.md` — экраны «Эксперта» обязаны ему следовать.

### Две стратегии работы с приложением (с `v1.29.0`)

В приложении две аудитории, и интерфейс обязан обслуживать обе, не смешивая их.

**«Просто работает» (режим «Простой», по умолчанию).** На главном экране — одна кнопка
**«Сделать, чтобы работало»** (`RunOneClickFixCommand`): проверка, подбор и включение обхода без вопросов
и без показа выбранного способа. Человек не выбирает технику — он хочет рабочий
обход. Правила: одна главная кнопка на экране («Сделать, чтобы работало» / «Проверить всё»), никаких
вопросов про стратегии, DNS, SNI, ipset, порты и аргументы; техническое не «серое», а отсутствует.
Если что-то не удалось — приложение пишет, что делать, и предлагает одно действие, а не список настроек.
Первый запуск — один экран (`FirstLaunchPage`), пошаговый мастер доступен только по кнопке
«Настроить по шагам» и не является путём по умолчанию.

**«Глубокий настройщик» (режим «Эксперт»).** Человек хочет контролировать и понимать. Ему нужен
рабочий стол, где видно связку «что применено → чем проверено → как откатить», а не разбросанные
по разделам переключатели. Этапы (см. `docs/HANDOFF.md`): `v1.29.1` — рабочий стол настройщика
(текущая конфигурация, аргументы, SNI, DNS-матрица, тесты, откат); `v1.30.0` — «под мою сеть»
(провайдер/ASN, ipset, порты, TCP-таймстемпы, DoH, IPv4/IPv6 одним сценарием с проверкой шагов);
`v1.31.0` — пресеты и откат (профили конфигураций, экспорт/импорт, возврат к предыдущей рабочей).

Правило проверки любого экрана: **в «Простом» не должно быть выбора, требующего технических знаний**;
**в «Эксперте» не должно быть элемента, для которого непонятно, что он меняет и как откатить**.

### Автопереключение стратегий (с `v1.28.1`)

**По умолчанию приложение не меняет стратегию само.** Автосмена — опт-ин: главный выключатель
`AppSettings.AutoSwitchStrategyEnabled` (галочка «Разрешить приложению менять стратегию автоматически»
в «Автоматизация → Восстановление») по умолчанию **выключен**, и пока он снят, ни один сценарий
(бесшовное переключение, сторож, мониторинг, фоновый подбор, автопрофиль при сбое) не имеет права
менять стратегию — только сообщать о недоступности и предлагать действие. Перезапуск **той же**
стратегии, ручные кнопки («Применить», «Подобрать замену сейчас», мини-оверлей, «Сделать основной»)
и мастер первого запуска работают независимо от выключателя.

Автоматическая смена стратегии — крайняя мера, а не фоновая оптимизация. Правила обязательны для
любого места, где приложение само меняет стратегию (`SeamlessFailoverService`, `WatchdogService`,
`MonitoringViewModel`, фоновая проверка в «Автоматизации»):

1. **Повод — только полная недоступность узла.** Смена разрешена, когда DNS не отвечает, TCP/TLS
   не поднимается или тайм-аут (`ResourceProbe.IsCompleteOutage`). Ответ сервера с HTTP 5xx,
   медленный узел, частичная деградация — **не** повод.
2. **Сбой подтверждается, а не берётся с одного замера.** Проверки идут через
   `ResourceProbe.CheckConfirmedAsync` (повтор при полной недоступности), решает подтверждённый
   результат; для серии — **3** сбоя подряд по одному узлу (было 2 — слишком дёргано).
3. **Кандидат проверяется на всём наборе узлов** через `BypassController.TestStrategyOnTargetsAsync`:
   он должен открыть сбойный узел **и** не сломать остальные. Лечить один сайт ценой другого нельзя.
4. **После переключения — постпроверка** (`VerifyAfterSwitchAsync`): если доступных узлов стало
   меньше или сбойный узел не открылся, приложение возвращает прежнюю стратегию и выдерживает
   cooldown. Переключение «ради скорости» и выбор «первой запустившейся» стратегии запрещены.
5. Пользовательские действия (кнопка «Применить», «Проверить всё», мини-оверлей, «Сделать основной»)
   правилами не ограничены — это осознанный выбор человека.

### Поиск `Ctrl+K` (с v1.24.0)

- Единый индекс — `Core/SearchCatalog.cs` (данные + скоринг, без UI) и `SearchViewModel` (действия: переход
  или уже существующая команда). Новый элемент интерфейса (раздел, подраздел, настройка, команда, сценарий
  «Помощи») **обязан** получить пользовательское имя и попасть в индекс — это требование §10.4, а не пожелание.
- У каждого пункта есть `Aliases`: старые и технические термины (`watchdog`, `бесшовное`, `матрица`, `SNI`,
  `DPI`, `Voice RTC`, `Deep Check`, `аудит`, `бэкап`, `SSID`) и гибрид «способ обхода»/«стратегия». Правка
  подписи подраздела без правки алиасов — ошибка: опытный пользователь перестанет находить место.
- Поиск ничего не выполняет сам: `SearchViewModel` не хранит состояние приложения, только строку запроса,
  выдачу, избранное и недавние (`SearchFavoriteIds`/`SearchRecentIds` в `AppSettings`).
- `Ctrl+K` регистрируется как комбинация окна (`Window.InputBindings`), а не глобальная: чужие программы
  клавишу не теряют. Кнопка поиска в шапке — вторая, видимая точка входа.

## 3. Сборка и проверка перед выдачей результата

```bash
# Сборка (работает и на Windows, и на Linux/macOS — включён EnableWindowsTargeting)
dotnet build src/ZapretGUI/ZapretGUI.csproj -c Release

# Проверка XAML: привязки, ключи стилей, обработчики Click
python3 tools/check_bindings.py

# Парсер стратегий на РЕАЛЬНЫХ .bat из релиза движка (без Windows)
#   распаковать релиз Flowseal в /tmp/engine и запустить:
dotnet run --project tools/StrategyParserHarness -- /tmp/engine

# Публикация портативного exe (как в GitHub Actions)
dotnet publish src/ZapretGUI/ZapretGUI.csproj -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none -o publish/portable
```

Сборка должна быть **без ошибок и предупреждений**. Запустить WPF-приложение на Linux нельзя —
Windows-специфичное поведение (запуск `winws.exe`, службы, трей, hosts) проверяется только на
Windows, поэтому в отчёте пользователю честно указывайте, что не проверялось в рантайме.
После `git push` обязательно дождитесь зелёного workflow (см. §6.5) — сборка на `windows-latest`
это финальная проверка.

## 4. Что нельзя ломать (контракты)

| Контракт | Где | Почему критично |
|---|---|---|
| Формат разбора `.bat` (строка с `winws.exe`, продолжения `^`, `%BIN%`/`%LISTS%`/`%~dp0`, `%GameFilterTCP%`/`%GameFilterUDP%`, `^!` → `!`) | `Core/StrategyParser.cs` | иначе обход запустится с неверными параметрами |
| Кавычки при `sc create` (`binPath= "\"…\winws.exe\" --аргументы"`) | `Core/BypassController.InstallServiceAsync` | служба не создастся или не запустится |
| Семантика режимов ipset: пустой файл = `any`, `203.0.113.113/32` = `none`, иначе `loaded`; реальный список в `ipset-all.txt.backup` | `EngineService.GetIpsetMode/SetIpsetMode` | совместимость с `service.bat` |
| `utils\game_filter.enabled` = `all`/`tcp`/`udp`; при выключенном фильтре порт-заглушка `12`, при включённом `1024-65535` | `EngineService`, `BypassController.BuildArgs` | иначе игры/сервисы не фильтруются |
| Имя службы `zapret` и значение реестра `zapret-discord-youtube` = имя стратегии | `Core/WinServices.cs` | совместимость с оригинальным менеджером |
| Блок `hosts` между маркерами `# ==== Zapret GUI … begin/end ====` + резервная копия | `EngineService.ApplyHosts` | безопасное обновление hosts вместо ручного копирования |
| Сохранение пользовательских файлов при апдейте | `EngineService.CopyEngine`, `IsUserFile` | иначе пользователь потеряет свои списки |
| Порядок обновления движка: стоп обхода → `sc stop zapret/WinDivert/WinDivert14` → пауза выгрузки драйвера → замена файлов; заблокированный `WinDivert64.sys` пропускать, а не перезаписывать | `BypassController.PrepareForEngineUpdateAsync`, `WinServices.StopForEngineUpdateAsync/WaitForDriverUnloadAsync`, `EngineService.CopyEngine` | иначе BSOD при обновлении «на лету» |

## 5. Как добавить страницу или настройку

**Страница:**
1. `Views/XxxPage.xaml` + `.xaml.cs` с конструктором, принимающим ViewModel (`DataContext = vm`).
2. `ViewModels/XxxViewModel.cs` (наследник `ObservableObject`, команды — `RelayCommand`/`AsyncRelayCommand`).
3. В `MainViewModel`: создать VM, добавить `NavItem { Key, Title, Icon }` в `NavItems`
   (глифы — из Segoe Fluent Icons/MDL2 Assets), зарегистрировать страницу в словаре `_pages`
   в `Views/MainWindow.xaml.cs`.
4. Стили брать из `Themes/Controls.xaml` (готовы: `Card`, `Badge`, `Dot`, `PrimaryButton`,
   `SecondaryButton`, `GhostButton`, `DangerButton`, `SwitchCheckBox`, `AppComboBox`,
   `SearchBox`, `RowItemStyle`, `SegmentedControl`, `ThinProgress` и т. д.).

**Настройка:** новое свойство в `Core/Settings.cs` → `AppSettings` (значение по умолчанию),
UI-свойство в `SettingsViewModel` (с `SettingsStore.Save`), по возможности — применение «на лету».

## 6. Цикл работы с пользователем (git-режим, без архивов)

**Вы вносите изменения прямо в репозиторий.** Пользователь только формулирует правки и проверяет
результат в собранном приложении. Архивы с исходниками больше не нужны.

Схема: `git clone/pull` → правки → проверки → `git commit` + `git push origin main` →
GitHub Actions (`.github/workflows/build.yml`) автоматически собирает приложение → вы дожидаетесь
результата и отчитываетесь ссылкой на артефакт (при необходимости — на релиз).

**Правила:**

1. **Доступ.** Токен (fine-grained PAT: `Contents: Read and write`, `Actions: Read`) пользователь
   передаёт в чате. Держите его в переменной окружения и подставляйте в URL remote'а:
   ```bash
   git clone https://x-access-token:$GITHUB_TOKEN@github.com/<логин>/<репозиторий>.git repo
   git config user.name  "zapret-gui-agent"
   git config user.email "agent@users.noreply.github.com"
   ```
   Токен **никогда** не коммитить, не писать в файлы репозитория и не выводить в отчётах.
   В песочнице агента `.git/config` и credentials не сохраняются между сессиями — при новой сессии
   заново подставьте токен: `git remote set-url origin https://x-access-token:$GITHUB_TOKEN@github.com/...`
   Если push отклонён (403/401) — сообщите пользователю и попросите новый токен.
2. **Перед первой правкой сессии:** `git pull --rebase` + три проверки (§3) и короткий отчёт
   пользователю о состоянии базы.
3. **Коммиты:** на русском, по существу изменения, без «fix» и «update» в одиночку.
   Пуш — в `main` по умолчанию; крупные/рискованные изменения — ветка `feature/*` + Pull Request.
4. **Версии:** поднимать `<Version>` в `src/ZapretGUI/ZapretGUI.csproj` — patch для правок,
   minor для новых функций, major для ломающих изменений. Релиз с готовым exe создаётся тегом:
   ```bash
   git tag v1.1.0 && git push origin v1.1.0
   ```
   Тег запускает публикацию GitHub Release (`ZapretGUI-<версия>-win-x64-portable.exe` + zip под .NET 8).
5. **Релиз обязателен для любой правки кода.** Пользователь обновляет приложение **только
   через GitHub Release**: встроенный апдейтер (`Core/GuiUpdateService.cs`, репозиторий
   `m0xvi/zapret-gui`) ищет в релизах ассет `ZapretGUI-<версия>-win-x64-portable.exe`, у которого
   есть `digest` SHA-256, и версию выше установленной. Без нового тега правка пользователю
   недоступна — «зелёного workflow» и артефакта Actions для этого недостаточно.
   Поэтому каждый цикл правок кода заканчивается так: зелёный CI → `git tag vX.Y.Z` →
   `git push origin vX.Y.Z` → проверить, что релиз создан и в нём оба ассета с digest
   (`gh api repos/<логин>/<репозиторий>/releases/tags/vX.Y.Z --jq '.assets[]|{name,digest}'`;
   `gh release view --json assets` поле `digest` не показывает — проверяйте через API).
   Если правка только в документации, тег не нужен.
6. **Проверка CI обязательна.** После push дождитесь завершения workflow и убедитесь в успехе:
   ```bash
   gh run list --limit 3        # или через API:
   curl -s -H "Authorization: token $GITHUB_TOKEN" \
     "https://api.github.com/repos/<логин>/<репозиторий>/actions/runs?per_page=3" \
     | jq -r '.workflow_runs[] | "\(.name) | \(.head_branch) | \(.status) | \(.conclusion) | \(.html_url)"'
   ```
   При падении — `gh run view <id> --log-failed`, исправить и запушить снова.
7. **Отчёт пользователю:** что изменено, статус сборки, ссылка на артефакт/релиз, что проверить
   в приложении вручную (Windows-специфичное — см. §3).
8. **Документация в том же коммите:** `README.md` при пользовательских изменениях,
   `docs/HANDOFF.md` при изменении архитектуры/контрактов, `docs/mockup.html` при изменении дизайна.

Токен пользователь выдаёт заново каждую сессию — спрашивайте, если он не подставлен или просрочен.
