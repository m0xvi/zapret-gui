## Как ты работаешь (важно)

**Ты вносишь изменения прямо в репозиторий — никакого архивирования и передачи файлов мне.**
Ты клонируешь репозиторий, правишь код, коммитишь, пушишь, дожидаешься сборки GitHub Actions
и присылаешь мне результат. Я только говорю, какие правки нужны, и проверяю результат.

Порядок каждой итерации:

1. **Подготовка окружения:**
   ```bash
   git clone https://x-access-token:$GITHUB_TOKEN@github.com/<ВАШ_ЛОГИН>/<РЕПОЗИТОРИЙ>.git repo
   cd repo
   git config user.name  "zapret-gui-agent"
   git config user.email "agent@users.noreply.github.com"
   ```
   Если репозиторий уже склонирован в этой сессии — просто `git pull --rebase`.
   Токен бери из переменной окружения, **не** коммить его и не записывать в файлы репозитория.
   (Учти: учётные данные не сохраняются между сессиями — при новой сессии снова подставь токен
   в URL remote'а: `git remote set-url origin https://x-access-token:$GITHUB_TOKEN@github.com/...`.)

2. **Проверка базы перед правками** (обязательно, если это начало сессии):
   ```bash
   dotnet build src/ZapretGUI/ZapretGUI.csproj -c Release
   python3 tools/check_bindings.py
   # парсер стратегий на реальном релизе движка:
   curl -L -o /tmp/engine.zip https://github.com/Flowseal/zapret-discord-youtube/releases/latest/download/zapret-discord-youtube-1.10.2.zip
   unzip -q /tmp/engine.zip -d /tmp && mv /tmp/zapret-discord-youtube-1.10.2 /tmp/engine
   dotnet run -p tools/StrategyParserHarness "/tmp/engine"
   ```
   Напиши мне коротко: база в порядке или что нашлось, и свой план правок.

3. **Внесение правок.** Всё на русском (код, комментарии, UI-тексты, коммиты). Соблюдай
   правила из `AGENTS.md`: не хардкодить стратегии, не ломать форматы `ipset`/`game_filter`,
   новые кисти только через `{DynamicResource}`, бизнес-логика в `Core/` и `ViewModels/`.

4. **Проверка после правок:** те же три проверки. Сборка — **без ошибок и предупреждений**.
   Если правил дизайн — синхронизируй `docs/mockup.html` (я сверяю правки по нему).
   Если правил поведение/структуру — обнови `README.md` и `docs/HANDOFF.md`.

5. **Коммит и push:**
   ```bash
   git add -A
   git commit -m "Стратегии: фильтр по провайдеру и сортировка по категориям"
   git push origin main
   ```
   Сообщение коммита — на русском, по существу, от лица сути изменения.
   Пуш в `main` — по умолчанию. Если правка крупная или рискованная, сделай ветку
   `feature/<короткое-имя>` и открой Pull Request, а мне дай ссылку.

6. **Версия.** Для новых функций поднимай `<Version>` в `src/ZapretGUI/ZapretGUI.csproj`:
   правки — patch (`1.0.1`), функции — minor (`1.1.0`), ломающие изменения — major.

7. **Релиз с готовым exe — обязательный финал любой правки кода, а не «когда попросят».**
   Правило проекта (`AGENTS.md` §6 п. 5): я обновляю приложение только через GitHub Releases
   встроенным апдейтером, поэтому правка без выпущенного тега для меня не существует.
   Изменения только в документации (`.md`, `mockup.html`) релиза не требуют.
   ```bash
   git tag v1.1.0 && git push origin v1.1.0
   ```
   Workflow на теге `v*` сам создаст GitHub Release с `ZapretGUI-<версия>-win-x64-portable.exe`
   и zip-версией под .NET 8.

8. **Дождаться сборки и отчитаться.** Не бросай push без проверки CI:
   ```bash
   gh run list --limit 3            # или, если gh недоступен:
   curl -s -H "Authorization: token $GITHUB_TOKEN" \
     "https://api.github.com/repos/<ВАШ_ЛОГИН>/<РЕПОЗИТОРИЙ>/actions/runs?per_page=3" \
     | jq -r '.workflow_runs[] | "\(.name) | \(.head_branch) | \(.status) | \(.conclusion) | \(.html_url)"'
   ```
   Если сборка упала — читай лог (`gh run view <id> --log-failed`), исправляй, пушь снова.
   Мне присылай: что изменено, статус сборки, ссылку на артефакт/релиз и что мне стоит проверить
   в приложении.

## Что важно про интерфейс (после этапов 1–8 IA)

- Структура зафиксирована в `docs/IA_REDESIGN.md`: **пять разделов** (Главная · Обход · Проверки ·
  Автоматизация · Настройки) плюс **«Помощь»** в подвале меню и **поиск `Ctrl+K`**. До подраздела —
  не больше двух кликов, до действия — один; функции не дублируются между разделами.
- По умолчанию включён режим **«Простой»**: технические блоки скрыты инлайн (`{Binding ExpertMode}`),
  «Эксперт» включается кнопкой в шапке, `Ctrl+Shift+E` или в «Настройках». Новую техническую функцию
  добавляй сначала в «Эксперт».
- **Новый элемент интерфейса обязан попасть в индекс поиска** (`Core/SearchCatalog.cs`) вместе
  с алиасами прежних/технических названий — иначе он теряется для пользователя.
- Старые термины остаются рабочими: «стратегия» и «способ обхода» ведут в одно место, а `watchdog`,
  `бесшовное`, `матрица`, `SNI`, `DPI`, `Voice RTC`, `Deep Check`, `аудит`, `бэкап`, `SSID` находятся
  поиском. Правка подписи без правки алиасов — ошибка.
- Ключи `Navigate` и `_pages` (`monitoring`, `dpi`, `deep-check`, `results`, `logs`, `strategies`,
  `user-lists`, `profiles`, `updates`, `about`) сохранены для трея, шапки и старых ссылок — не удаляй их.

## Ограничения, которые надо помнить

- Windows у тебя нет: WPF-приложение запустить нельзя. Логику проверяй сборкой, `check_bindings.py`
  и harness'ом, а всё Windows-специфичное (запуск `winws.exe`, службы, трей, hosts) честно
  помечай как «нужно проверить на Windows» — я прогоню exe и пришлю журнал со страницы «Журнал».
- GitHub API без токена ограничен 60 запросами в час — в само́м приложении это уже учтено
  (резервный путь через `.service/version.txt`), не добавляй опрос API по таймеру.
- Ничего не удаляй из репозитория без моей просьбы. Никогда не коммить бинарники zapret
  (`winws.exe`, `WinDivert*`, `*.bin`, списки) и токены.
