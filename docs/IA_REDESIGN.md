## 1. Аудит текущей структуры (по коду, не по документу)

### 1.1 Факты

| Факт | Где видно | Почему это проблема |
|---|---|---|
| В меню 5 пунктов, а реальных экранов 15 | `MainViewModel.NavItems` vs словарь `_pages` в `MainWindow.xaml.cs` | пользователь не знает о существовании половины функций |
| `Обновления`, `Журнал`, `О программе`, `Мониторинг`, `Первый запуск` недостижимы из меню | `NavItems` содержит только `home, bypass-center, strategies, diagnostics, user-lists, profiles, settings` | попасть можно лишь случайно, через ссылку внутри другой страницы (обновления — из «Настроек», «О программе» и «Обзора»; журнал — из «Настроек», «О программе», трея) |
| `MonitoringPage` — **мёртвый экран** | `_pages["monitoring"]` есть, но `Navigate("monitoring")` принудительно переводит на `diagnostics` (таб 0) | дублирующий UI-код, который надо сопровождать; правильный экран — таб «Экспресс», который вообще-то и есть мониторинг |
| Таб «⚡ Экспресс» в «Проверке» — это UI мониторинга ресурсов | `DiagnosticsPage.xaml` строки 45–160: `Monitoring.Targets`, `CheckAllCommand`, «ЭКСПРЕСС-ПРОВЕРКА РЕСУРСОВ» | название таба не совпадает с содержимым; «Мониторинг» существует в 4 обликах |
| Три владельца игрового фильтра | `HomePage` («ФИЛЬТРЫ · ДЛЯ ПРОДВИНУТЫХ»), `UserListsPage`, `SettingsPage→Игры` | пользователь не знает, какой из них «настоящий»; рассинхрон значений |
| Три владельца ipset | `HomePage`, `UserListsPage`, `SettingsPage→Обход` | то же |
| Три владельца DNS | `BypassCenterPage`, `UserListsPage`, `SettingsPage→Сеть` | то же |
| «Настройки» — 8 табов, включая «Журнал» и «О программе», которые есть ещё и отдельными страницами | `SettingsViewModel.SettingsTabs` | две реализации одного экрана |
| 6 табов в «Проверке»: Экспресс, DPI, Deep Check, Аудит, Результаты, Voice RTC | `DiagnosticsViewModel.DiagnosticsTabs` | смешаны 4 разные задачи (мониторинг, проверка DPI, аудит, отчёты) под одним словом «Проверка» |
| Главный экран содержит мастер из 4 шагов (~1–2 мин), игровой блок, «продвинутые фильтры», отдельную проверку соединения | `HomePage.xaml`, 578 строк | главный экран перестал быть «статус + одно действие» |
| Слово «игра» означает 3 разные функции | «Игровой режим» (рантайм), «Автодетект игр / автовключение» (настройка), «Игровой фильтр» (порты) | ментальная склейка несвязанного |

### 1.2 Где что лежит сейчас — тепловая карта дублей

| Функция | Мест сейчас | Где именно |
|---|---|---|
| Игровой фильтр (порты) | **3** | Главная, Списки, Настройки→Игры |
| ipsets (режим, обновление) | **3** | Главная, Списки, Настройки→Обход |
| DNS (профиль, DoH, подмена) | **3** | Центр обхода, Списки, Настройки→Сеть |
| Мониторинг ресурсов | **4** | Проверка→Экспресс, мёртвая MonitoringPage, Настройки→Сеть (фон), Настройки→Интерфейс (RTT/метрики) |
| Обновления (движок/GUI) | **4** | Обновления (скрыта), Настройки→Обновления, О программе, Главная |
| Журнал | **4** | Журнал (скрыта), Настройки→Журнал, О программе, меню трея |
| Выбор/применение стратегии | **3** | Стратегии, Центр обхода (комбо), Главная (мастер) |
| Watchdog / бесшовное переключение | **3** | Настройки→Обход, Центр обхода (чекбокс+статус), бейджи в меню |
| Автозапуск | **2** | Настройки→Общие (приложение), Настройки→Обход (обход) — плюс Первый запуск |
| Телеметрия/экспорт отчётов | **3** | Проверка→Экспорт, DPI-экспорт, Настройки→Сеть (телеметрия провайдера) |

### 1.3 Корневые причины

1. **Разделы проектировались по техническим сущностям** («Списки», «Профили», «Проверка»), а не по задачам («сделай, чтобы работало»).
2. **«Центр обхода» — свалка «всё в одном»**: стратегии + DNS + hosts + ipset + твики YouTube + матрица 92 теста на одной странице. Следствие — дубли: пользователь не помнит, где «настоящие» настройки, поэтому их продублировали на Главной и в других разделах.
3. **Нет уровня раскрытия**: новичок видит ровно то же, что эксперт (BFE, WinDivert, PID, SNI, ipset any/none/loaded).
4. **Нет страховки навигации**: нет поиска/избранного/недавних, поэтому спрятать техническое «некуда» — приходится держать всё на поверхности.

## 2. Целевая структура: 5 разделов + «Помощь»

| № | Раздел | Задача пользователя | Что внутри | Частота |
|---|---|---|---|---|
| 1 | **Главная** | «Работает или нет? Включить/выключить.» | статус обхода, одна кнопка питания, плитки состояния, «требует внимания», ссылки «не работает?» | ежедневно |
| 2 | **Обход** | «Как именно обходим: чем, через что, какие сайты и игры.» | способ обхода, подбор, DNS, списки/hosts/ipset, сложные сайты (YouTube/Discord), режим службы | недели |
| 3 | **Проверки** | «Что-то не работает — найди причину и починить.» | быстрая проверка сайтов, DPI/звонки, система (аудит+исправления), глубокая проверка, история/отчёты, журнал | по проблеме |
| 4 | **Автоматизация** | «Пусть работает и чинится само.» | запуск при старте, автоперезапуск, бесшовное переключение, расписание, профили по сетям, фоновый контроль | настроил один раз |
| 5 | **Настройки** | «Настроить само приложение и мои данные.» | оформление, уведомления, горячие клавиши, движок и обновления, профили/копии, о программе | редко |
| — | **? Помощь** (подвал меню) | «Не знаю, что делать.» | 6 сценариев «не работает» с шагами и переходами + отправка отчёта | по проблеме |

**Почему «Помощь» стоит отдельно от пяти разделов** (решение владельца продукта: помощь нужна новичку): она отделена визуально (подвал меню, после разделителя, глиф `?`), не имеет ни одной настройки и ни одного собственного контрола — только сценарии, тексты и **переходы** в существующие места. Так «верхний уровень» остаётся пятью равнозначными разделами, а шестой пункт работает как вход, а не как ещё один раздел. Если позже понадобится строгий лимит «5 пунктов в меню» — «Помощь» без изменений переезжает в кнопку `?` в шапке/трее.

**Правило размещения (проверка при добавлении любой новой функции):**

| Вопрос | Раздел |
|---|---|
| Отвечает «включено или нет» и требует 1 действия? | Главная |
| Меняет параметры обхода (чем, что, как)? | Обход |
| Ищет причину сбоя, тестирует, исправляет? | Проверки |
| Работает по таймеру/событию без пользователя? | Автоматизация |
| Настройка самого приложения, обновления, данные? | Настройки |
| Объясняет, что делать при типовой проблеме? | Помощь (только сценарий + переход, ни одного своего контрола) |

Если функция подходит под два раздела — она размещается по «первому владельцу», а во втором месте ставится **ссылка или контекстное действие** (например, кнопка «Добавить в обход» у проблемного сайта в «Проверках» — это действие, а не второй список).

## 3. Дерево разделов

Уровни: **[О]** основной (видит новичок), **[Д]** дополнительный (виден всегда, но второстепенен), **[Э]** экспертный (только в режиме «Эксперт»).

### 3.1 Главная — «Статус и кнопка»

| Блок | Содержимое | Ур. |
|---|---|---|
| Карточка обхода | состояние (включён / выключен / ошибка), текущая стратегия одной строкой, время работы, **кнопка «Включить / Выключить обход»** — единственное крупное действие на экране | [О] |
| Плитки состояния (3 шт.) | «Соединение: OK 26/28, ср. 42 мс», «Игровой режим: вкл/выкл», «Автопилот: следит / выключен» | [О] |
| «Требует внимания» (условный блок) | появляется только при проблеме: нет прав администратора · служба не установлена/остановлена · конфликт со старым zapret · движок не найден · списки не обновлялись · доступно обновление. Формат: 1 проблема = 1 кнопка действия + «подробнее» → Проверки | [О] |
| «Не работает?» | 3 ссылки: «Подобрать обход заново» → Обход→Подбор · «Проверить сайты» → Проверки · «Открыть журнал» → Проверки→Журнал | [О] |
| Служебная строка | режим работы (служба/процесс), PID, версия движка, режимы hosts/ipset, «Переустановить службу», «Открыть папку движка» | [Э] |
| Переключатель «Экспертный режим» | в шапке рядом с версией | [Э] |

Чего на Главной **нет**: мастеров, тестов, фильтров, списков, настроек YouTube, тумблеров DNS, логов.

### 3.2 Обход

| Подраздел | Содержимое | Ур. |
|---|---|---|
| **Способ обхода** | в «Простом» режиме назван «Способ обхода»: текущий вариант + человеческое описание; список с поиском и фильтром по категориям; «Применить»; «Проверить этот способ» (~15 с). В «Эксперте» тот же подраздел подписан «Стратегия» и показывает технические имена (`ALT11`, `GENERAL`), аргументы `winws` (`ArgsPreview`), кандидатов, пул SNI, историю переключений и оценок | [О]/[Э] |
| **Подбор** | «Подобрать обход заново» — 4 шага (аудит → сайты → все стратегии → рекомендация) + «Применить». Экспертно, свёрнуто: «Перебор с разными DNS» (матрица 23×4 = 92 теста) с отменой и восстановлением исходного состояния | [О]/[Э] |
| **DNS** | текущий DNS, профили (Cloudflare/Quad9/Google/DHCP), «Применить», DoH для заблокированных, «Проверить подмену» | [О] |
| **Списки** | 4 блока: **Мои сайты** (добавить домен/удалить, `list-*-user.txt`), **Списки** (general/youtube/discord + счётчики, обновить, «Списки OK»), **hosts** (состояние, применить/обновить/восстановить, открыть в блокноте), **ipset** (режим loaded/none/any, размер, обновить). Обновление списков: вручную / автоматически (`.bat`) | [О]/[Э] |
| **Сложные сайты** | 3 карточки-пресета: «YouTube не грузит» · «Discord Voice не работает» · «Тяжёлые игры». Внутри пресета — готовое действие. Экспертно разворачивается в отдельные тумблеры: QUIC-fake, подмена SNI, предпочтение IPv4, DoH для заблокированных, host-specific стратегии | [О]/[Э] |
| **Дополнительно** | режим работы (служба Windows / отдельный процесс), установить / переустановить / удалить службу, показывать консоль `winws`, папка движка, откат на предыдущую стратегию | [Э] |

**Гибридное название (решение владельца продукта):** «Способ обхода» — в «Простом» режиме, «Стратегия» — в «Эксперте» и в технических контекстах (лог, отчёт, трей «Смена стратегии»). Поиск `Ctrl+K` обязан находить подраздел по **обоим** словам: «стратегия» и «способ обхода» — это требование к индексу поиска, а не пожелание. Внутри карточки оба термина сходятся: «ALT11 — способ обхода через подмену пакетов».

### 3.3 Проверки

| Подраздел | Содержимое | Ур. |
|---|---|---|
| **Быстрая проверка** | список сайтов/сервисов с статусом и задержкой; «Проверить всё» (~10 с, без остановки обхода); клик по сайту → «Определить причину» (провайдер / стратегия / сервер недоступен); добавить свой сайт или игру; «Следить в фоне» + интервал 5–120 мин; уведомления; «Показывать задержку на панели задач» + выбор целей и позиция | [О] |
| **Сложные сайты и звонки** | DPI-проверка по 34 узлам; проверка голоса Discord (Voice RTC) + «Применить исправление». Результат — «Ваш провайдер фильтрует TCP/TLS/QUIC» человеческим языком | [О] |
| **Система** | аудит 14 пунктов (права администратора, BFE, WinDivert, TCP timestamps, служба `zapret`, hosts, ipset, DNS) с оценкой и кнопкой «Исправить» у каждого; сверху — «Исправить всё безопасное». Внизу под раскрытием: опасные операции (переустановить/удалить службы, полный сброс сети) с подтверждением | [Д]/[Э] |
| **Глубокая проверка** | свои хосты (`targets.txt`), контекст провайдера и региона, многоточечная проверка с отчётом, найденными проблемами, рекомендациями и «Сохранить/Применить найденный вариант» | [Э] |
| **История и отчёты** | результаты проверок, история переключений стратегий, журнал восстановлений; экспорт JSON/ZIP; «Отправить отчёт» (телеметрия провайдера — по согласию) | [Д] |
| **Журнал** | по умолчанию фильтр «Только важное» (предупреждения/ошибки); переключатель «Всё (отладка)»; поиск по тексту; «Копировать», «Очистить», автопрокрутка; «Открыть папку логов» | [О]/[Э] |

### 3.4 Автоматизация

| Подраздел | Содержимое | Ур. |
|---|---|---|

## 5. Переименования «было → стало»

| Было | Стало | Почему |
|---|---|---|
| Обзор | **Главная** | «Обзор» обещает дашборд с метриками; на деле это «статус + выключить/включить». «Главная» = с неё начинают |
| Центр обхода | *(раздел упразднён)* | «Центр» не сообщает, что внутри; «всё в одном» — источник дублей. Подразделы живут внутри «Обхода» |
| Проверка (nav) | **Проверки** (подзаголовок «Проверить и починить») | единственное число читалось как «одна проверка»; в разделе 6 разных инструментов + починка |
| Мониторинг / Экспресс-проверка ресурсов | **Быстрая проверка** | одно и то же называлось двумя словами; «мониторинг» — слово разработчика |
| DPI 34 узла | **Сложные сайты и звонки** | «DPI», «34 узла» описывают реализацию, а не задачу («проверить, почему не грузит YouTube/звонок») |
| Voice RTC | *(внутри)* «Проверка голоса Discord» | аббревиатура ничего не говорит пользователю |
| Аудит | **Система** (подраздел «Проверка системы») | «аудит» — из бухгалтерии/безопасности; «Система» честно говорит: проверяем Windows и драйверы |
| Deep Check / Глубокая проверка | **Глубокая проверка** (остаётся) | термин уже понятен тем, кто им пользуется; остаётся экспертным |
| Watchdog | **Присмотр за обходом (автоперезапуск)** | в UI слово-собака ничего не объясняет; «watchdog» остаётся только в логах |
| Seamless / Бесшовное переключение | **Переключение при ухудшении** | «бесшовное» описывает способ, а не результат («сам переключится на рабочий вариант») |
| Матрица 92 теста | **Перебор с разными DNS** | «матрица 23×4=92» — язык тестировщика |
| Стратегия (*в простом режиме*) | **Способ обхода** | гибрид: в «Простом» — бытовое слово, в «Эксперте» и в технических контекстах (лог, отчёт, трей) остаётся привычное «Стратегия». Поиск индексирует оба |
| Смена стратегии (трей) | **Смена способа обхода** | меню трея читает новичок; технический ярлык «Стратегия ALT11» остаётся в подзаголовке карточки |
| Игровой режим / Игровой фильтр / Автодетект игр | **Игровой режим** (переключатель) / **Фильтр трафика игр** (порты) / **Автовключение игрового режима** (правило) | три разных функции назывались похоже — источник ошибок |
| Профили | **Профили и копии** (Н) и **Профили по сетям** (А) | «профиль» = объект, «по сетям» = правило; так видно, что это разные вещи |
| Обновления | **Движок и обновления** (Н) | уточняет, что обновляется движок и само приложение |
| Журнал | **Журнал** (внутри Проверок) | слово уже правильное, меняется только место: журнал нужен, когда диагностируешь |
| О программе | **О программе** (внутри Настроек) | редко используемое — глубже, но находится поиском |
| ipset / hosts / `list-*.txt` | внутри **Списки** → «ipset», «hosts», «Мои сайты» | оставляем профессиональные слова в экспертной части, но группируем в один понятный подраздел «Списки» |
| Списки | **Списки** (внутри Обхода) | сохраняется привычное слово, но занимает подчинённое место |

## 7. Режимы «Простой» и «Эксперт»

**Статус: реализовано в `v1.22.0` (этап 5).** Все скрытия из таблицы ниже сделаны инлайн через
`ExpertMode`; опасные операции подтверждаются в обоих режимах, миграционный баллун работает.

**По умолчанию — «Простой».** Режим меняет не структуру, а **глубину раскрытия** (инлайн, без переездов): скрытые блоки остаются на своих местах и разворачиваются на месте, поэтому ментальная карта не ломается.

| Область | Простой (по умолчанию) | Эксперт |
|---|---|---|
| Главная | карточка обхода, плитки состояния, «требует внимания», 3 ссылки | + режим служба/процесс, PID, версия движка, режимы hosts/ipset, «Переустановить службу» |
| Обход → Стратегия | список, «Применить», «Проверить эту», описание человеческим языком | + аргументы `winws`, категории, SNI-пул, кандидаты, история оценок |
| Обход → Подбор | 4 шага и «Применить» | + «Перебор с разными DNS» (92 теста) |
| Обход → Списки | счётчики, «Обновить», «Мои сайты», hosts вкл/выкл | + ipset режимы `loaded/none/any`, пути к файлам, открыть в блокноте |
| Обход → Сложные сайты | 3 пресета | + QUIC-fake, подмена SNI, IPv4, DoH, host-specific стратегии |
| Обход → Дополнительно | скрыт целиком | режим службы, установка/удаление, консоль `winws` |
| Проверки | «Проверить всё», причина «провайдер/стратегия/сервер», DPI-набор, «Исправить», журнал «Только важное» | + «Система» (14 пунктов), «Глубокая проверка», «История и отчёты», опасные операции, «Всё (отладка)» |
| Автоматизация | тумблеры запуска, автоперезапуск, «переключаться при ухудшении», расписание | + интервалы, кулдауны, коoldown, «Что делал автопилот», таблица сетей |
| Настройки | тема, уведомления, обновления движка/приложения, профили, о программе | + метрики панели задач, горячие клавиши, телеметрия, экспорт/импорт, опасные операции |

**Правила режима:**

1. Переключение — в шапке (`Ctrl+Shift+E`) и дублируется в Н → Приложение; текущий режим виден как «Эксперт» рядом с версией.
2. Экспертный режим **не снимает защиту**: опасные операции (удаление службы, сброс сети, «очистить систему») всегда требуют подтверждения — в обоих режимах.
3. Обычные действия обхода подтверждений не требуют (сохраняем решение v1.17.24 — без `MessageBox` на старт/стоп).
4. Миграция существующих пользователей: если в `AppSettings` есть нестандартные значения экспертных параметров (SNI, матрица, host-specific стратегии), при первом запуске новой версии показывается один баллун трея: «У вас настроены продвинутые параметры. Включить режим „Эксперт“?» — без модального окна.
5. Новая функция добавляется сначала в «Эксперт», и только если ей пользуются часто (по телеметрии/фидбеку) — поднимается в «Простой».

## 10. Обоснование решений

### 10.1 Когнитивная нагрузка

| Решение | Обоснование |
|---|---|
| 5 разделов вместо 9 пунктов/15 экранов | закон Хика + 7±2: время выбора логарифмически растёт с числом равнозначных вариантов; 5 пунктов просматриваются за один взгляд |
| Разделы по задачам, а не по сущностям | «Списки», «Профили», «Проверка» — это то, как устроена программа; «Обход», «Проверки», «Автоматизация» — то, что человек делает. Пользователь ищет глагол, а не сущность |
| Один подраздел = одна задача | запрещает «Центр обхода»: страница, где всё в одном, не имеет ответа на вопрос «где это искать» и провоцирует дубли |
| Главная = статус + 1 действие | главный экран читается за 3 секунды: «включено/выключено» + большая кнопка. Всё, что не требует действия сейчас, переехало вглубь (правило «state-driven, не feature-driven») |
| Прогрессивное раскрытие | то, что делают ежедневно (питание, проверка, игровой режим) — на поверхности; то, что делают раз в жизни (матрица 92 теста, ipset `any/none`, сброс сети) — 2–3 клика и режим «Эксперт» |
| Разведение трёх «игровых» функций | разные названия вместо похожих снимают типовую ошибку «нажал не то» |
| Сквозные трей/хоткеи/мини-оверлей | частые действия доступны без навигации: это алиасы одной команды, а не дубли, поэтому не увеличивают нагрузку выбора |

### 10.2 Ментальные модели

* **«Пульт → настройка → автопилот → ремонт → сервис».** Порядок разделов повторяет жизненный цикл: включил → настроил → доверил → починил → обслужил.
* **«Обход» = то, что обходим и чем.** Пользователь говорить «включить обход», а не «запустить стратегию»; поэтому раздел назван словом из кнопки, а «стратегия» осталась внутри как инструмент.
* **«Автоматизация» как явная сущность.** В приложении уже есть сложный автопилот (Watchdog, Seamless, расписание, автопереключение профилей, фоновый мониторинг), но он был рассыпан по 4 экранам. Отдельный раздел = «здесь живёт то, что работает без меня».
* **Диагностика = ремонт, а не отчёт.** Раздел называется «Проверки», но первая кнопка внутри — «Проверить», а у каждого пункта есть «Исправить»: пользователь приходит с проблемой и уходит с решением.
* **«Движок» — не пользовательская сущность.** Скачивание/пути/версии `winws.exe` переехали в настройки; на поверхности остаётся строка «Движок готов · v1.10 · 22 стратегии».
* **Два языка на одну сущность — управляемо.** Гибрид «Способ обхода» / «Стратегия» безопасен потому, что меняется **только подпись подраздела**, а не расположение: пользователь, переключивший режим, не теряет место, в котором был. Оба термина живут в одной карточке («ALT11 — способ обхода через подмену пакетов»), и оба проиндексированы поиском, поэтому «стратегия» остаётся рабочей командой для опытных.
* **«Помощь» отделена от разделов, чтобы не стать шестым «Настройками».** Она не хранит состояние и не содержит уникальных контролов: если сценарий начинает требовать своей настройки — значит, место функции в «Обходе», «Проверках» или «Автоматизации», а в «Помощи» остаётся переход. Это защита от превращения помощи в свалку.

### 10.3 Баланс функционала: частота × критичность → глубина

| Функция | Частота | Критичность | Уровень |
|---|---|---|---|
| Включить/выключить обход | ежедневно | критично | Главная, 0–1 клик |
| Проверить, «работает ли YouTube/Discord» | несколько раз в неделю | высоко | Проверки → Быстрая проверка |
| Игровой режим | по сессии игры | средне | Главная + хоткей |
| Сменить стратегию | 1–2 раза в месяц | высоко | Обход → Стратегия |
| Автозапуск, автоперезапуск | настроил один раз | критично (после сбоя) | Автоматизация (видимый тумблер) |
| Расписание, профили по сетям | настроил один раз | средне | Автоматизация → подразделы |
| DNS, hosts, списки | редко | средне | Обход → подразделы |
| Обновления движка и приложения | раз в месяц | средне | Настройки + строка-статус на Главной |
| Матрица 92 теста, SNI-пул, ipset-режимы, сброс сети | раз в жизни | низко/опасно | Эксперт, 3 клика, подтверждение |
| Журнал | при разборе сбоя | средне | Проверки → Журнал + `Ctrl+K` |

### 10.4 Почему «страховка» (поиск/избранное/недавние) важна именно здесь

Глубина 2 уровня + режим «Простой» неизбежно что-то прячет. Чтобы «спрятанное» не превращалось в «потерянное»:

* `Ctrl+K` — единый поиск: названия разделов, подразделов, настроек и **команд** («включить обход», «днс», «журнал», «расписание», «SNI») → переход + подсветка нужной карточки;
* «Недавние» (5 последних мест) и «Избранное» (звёздочка у любой карточки) живут **внутри поиска**, а не на Главной, — чтобы Главная не превратилась в свалку ярлыков;
* новый элемент, добавленный в интерфейс, обязан иметь пользовательское имя и попадать в индекс поиска (это требование к разработке, а не пожелание);
* **старые термины остаются рабочими командами**: после переименований поиск обязан находить функции по прежним словам — `watchdog`, `бесшовное переключение`, `матрица`, `SNI`, `DPI 34 узла`, `Voice RTC`, `Deep Check`, `аудит`, `бэкап`. Опытный пользователь не должен переучиваться: он вводит привычное слово и попадает в новое место. В прототипе это реализовано полем `alias` у подразделов и блоков и проверено по 24 запросам.

## 11. Tree testing: задачи и метрики

**Метод:** tree testing по меню/подразделам без визуального дизайна (прототип `docs/ia_prototype.html`), затем повтор на кликабельном макете. Сравнение «старое дерево vs новое» — внутригрупповое, порядок рандомизируется. Участники: 10–12 человек (5 новичков без опыта zapret, 5 опытных пользователей текущей версии, 2 «продвинутых»).

| # | Задача (формулировка пользователю) | Ожидаемый путь | Правильный ответ |
|---|---|---|---|
| T1 | «Включите обход» | Главная | кнопка «Включить обход» |
| T2 | «Проверьте, работает ли YouTube через обход» | Проверки → Быстрая проверка | YouTube в списке / «Проверить всё» |
| T3 | «Сделайте так, чтобы обход включался сам после перезагрузки Windows» | Автоматизация → Запуск | «Включать обход при старте приложения» |
| T4 | «Добавьте сайт `example.com` в обход» | Обход → Списки | «Мои сайты» → «Добавить домен» |
| T5 | «Настройте, чтобы при сбое приложение само переходило на запасную стратегию» | Автоматизация → Восстановление | «Переключение при ухудшении» |
| T6 | «Узнайте, почему вчера отключился обход» | Проверки → Журнал (или История и отчёты) | события за вчера |
| T7 | «Выберите другую стратегию обхода» | Обход → Стратегия | список стратегий |
| T8 (доп.) | «Настройте, чтобы в домашней сети применялись свои настройки» | Автоматизация → Профили по сетям | «сеть → профиль» |
| T9 (доп.) | «Посмотрите, что не так с драйвером/правами в системе» | Проверки → Система | аудит 14 пунктов |
| T10 (новички) | «Перестал открываться YouTube — что делать?» (поиск не подсказывать) | Помощь → «Не открывается YouTube» *или* Проверки → Быстрая проверка | любой из двух путей считается успехом; фиксируем, какой выбран |
| T11 (новички) | «Как включить обход вручную?» | Главная | кнопка питания |
| T12 | «Найдите, где включить «Стратегию» (технический термин)» | Обход → Способ обхода **или** `Ctrl+K` → «стратегия» | проверка гибридного названия: оба пути успешны |

**Метрики и пороги успеха:**

| Метрика | Как считаем | Порог |
|---|---|---|
| Успех задачи | дошёл до правильного места без подсказки | ≥ 90% |
| Успех с первой попытки | без возврата «назад» и без повторного выбора | ≥ 80% (для T10/T11 у новичков — ≥ 70% на первом тесте) |
| Время выполнения | медиана на задачу (T1 ≤ 5 с, T6/T8 ≤ 25 с, остальные ≤ 20 с) | медиана ≤ 20 с |
| Количество кликов | медиана по задачам; T1 = 1, все остальные ≤ 3 | ≤ 3 |
| Ошибки | доля неверных первых кликов + доля «сдался» | ≤ 10% / ≤ 5% |
| Прямой путь | доля решений без поиска (поиск — страховка) | ≥ 70% |
| Удовлетворённость | SEQ (1–7) после каждой задачи; UMUX-Lite после теста | SEQ ≥ 6.0; UMUX-Lite ≥ 80 |
| Сравнение с текущим деревом | Δ по успеху и времени между старым и новым деревом | улучшение успеха ≥ +25 п.п. на T3/T5/T6 |

Дополнительная проверка после внедрения (реальная телеметрия приложения, без персональных данных): доля сессий, где «Экспертный режим» вообще не включался (цель ≥ 85%); доля переходов из «требует внимания» (цель ≥ 60% — значит блок полезен, а не раздражает); доля обращений к `Ctrl+K`.

### 14.1 Риски принятых решений и как их закрываем

| Риск | Оценка | Митигация |
|---|---|---|
| «Помощь» — 6-й пункт меню, формально нарушает «≤5 разделов» | низкий: это утилита в подвале, без настроек и состояния | отделяем визуально (разделитель, подвал, глиф `?`); правило «ни одного своего контрола — только сценарий и переход» проверяется на код-ревью; при необходимости переезжает в кнопку `?` в шапке без изменения содержимого |

### 14.2 Что осталось открытым (не блокирует внедрение)

1. **Точный состав фраз «Как это работает»** (5 объяснений про обход, стратегию, службу, DNS) — тексты пишутся отдельно, структура от них не зависит.
2. **Порядок сценариев в «Помощи»** — по умолчанию по частоте обращений (YouTube → Discord → интернет → игры → вернуть как было), уточняется после первых 2 недель по статистике переходов.
3. **Кому адресован «Экспертный режим» по умолчанию** при обновлении с текущей версии: если в профиле есть нестандартные экспертные значения — показываем один баллун предложения (§7, п. 4); нужно ли запоминать отказ — решается на этапе 5 плана внедрения.
